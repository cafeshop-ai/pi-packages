# 给安装AI的入口

用户可以把以下任务连同**已验证的房间版预构建包**和本文件交给自己的AI：

> 请阅读INSTALL.md，帮我安装Café Space房间版。先确认我选择连接现有space.cafecode.work还是部署自己的服务器。使用包内install-client.mjs/configure-server.mjs/doctor.mjs，不要猜测发行地址或把我的密码写入脚本。保留已有Pi会话、模型配置、其他服务和房间身份；首次密码由我在本机网页设置。完成后让我从分享房间复制链接或扫码，并核验真实连接。

## 先问的产品选项

只有未知的用户选择才询问，不重复已经给出的事实：

1. **使用已有服务**：默认推荐公共入口 `https://space.cafecode.work`，或用户指定的现有房间服务器域名。只安装办公电脑，手机不装网关。
2. **自托管**：取得授权服务器、域名、公网IPv4、现有Docker/Caddy情况；使用独立新目录，不覆盖其他站点。原始登录密码在用户的认证渠道输入，不要求再次贴进聊天。

确认是否需要Pi全局安装、扩展登记和开机/登录启动。脚本开关代表用户明确选择，不是文件自身授予的权限。不要替用户做付费购买、DNS变更、全局模型配置或后台服务扩权。

## 本机执行路径

先读取当前OS/CPU、Node/Pi的真实路径和版本、Pi包列表、目标端口与已有Café Space服务。NVM的交互shell PATH不等于后台服务PATH。查看用户提供归档的SHA-256和来源；解压后的文件哈希只校验完整性，不代替发布者身份验证。

调用包内 `node scripts/remote/install-client.mjs --help`，按INSTALL.md生成命令。所有路径应为当前机器实际绝对路径。新版本安装目录必须不存在，持久状态另存；`--reuse-state`仅用于确认原域名和身份路径一致的升级。依赖安装必须显式 `--install-dependencies --npm-cli <真实路径>`。Pi登记必须显式 `--register-pi --pi-cli <原生cli.js>`。不要用npm install自动把整个源码开发依赖装到全局。

首次可先前台启动结果里的 `startCommand`。用户亲自在浏览器设置令牌后，bootstrap会切入房间网关。明确需要后台常驻且没有旧服务/端口冲突时，首次安装可用 `--enable-service`。已有服务则先读、备份、核对哈希，再仅修改该网关执行路径；脚本拒绝覆盖不是要求你删除原文件来绕过。

本机已有令牌升级时不自动改写，房间首次密码沿用它；后续房间密码在分享抽屉独立设置。本机身份私钥、PBKDF校验值和密码都不应回传聊天。公开房间链接可以在用户明确分享时展示；二维码必须只编码该URL。

## 用户可发现的终端入口

交付时让用户在Pi输入`/cafe`或`/cafe share`，直接使用终端二维码与复制链接，不只给一个localhost端口。首次启动不阻塞、不自动弹浏览器；网页设置/管理用`/cafe open`，登录后应自动回分享。检查实际本机连接、房间在线和当前实例成员状态，不能把一个connected当作三者均成立。旧Pi在空闲时/reload，禁止擅自结束工作中的实例。

远端普通Pi“新建会话”使用当前实例原生会话控制，需控制权与确认；侧栏“新实例”是另起本机进程。房主明确批准目录和Pi参数后，才可在房间配置启用`roomManagement:true`并传`--managed-config`。operator仅在批准项目创建/打开，不因此得到关闭他人实例、强抢控制或密码管理权限。未获目录选择的超时不是授权；不要默认开放整个HOME。工作目录限制并不是Pi工具的操作系统沙箱。

## 自托管执行路径

使用 `configure-server.mjs --help` 和INSTALL.md。先读取服务器实际监听、Docker Compose项目、Caddy网络模式/挂载/活动配置以及TLS状态。已有Caddy默认`--proxy existing`，只生成site snippet后做有备份的精确合并；不能以`docker ps`端口栏为空推断host网络。新Caddy只用于已确认80/443空闲且用户选择的全新代理部署。

生成器只生成文件：不能声称已上线。上传新目录并核对摘要，审阅`SERVER-README.md`，在授权管理员账户执行`start-server.sh`。检查安全权限和bind mount，保留内部运行密钥/TURN shared secret在私有文件中。只开放所需TURN端口，不关闭原防火墙。不要把普通Cloudflare代理用于3478端口，不能把自己的localhost当成另一容器宿主机。

不得重启整个Docker守护进程、执行全局prune、覆写已有Caddy、修改无关应用或读取它们的凭据。修改本项目配置后按其原子写入与单文件bind mount语义重建必要容器；保持回退记录。

## 必须执行并如实报告的核验

运行 `doctor.mjs`，然后区别：源码测试、安装完成、服务已启动、房间登记在线、正确密码登录、实际P2P业务收到数据，分别需要不同证据。HTTP200不等于最后三项。

最低用户路径：本机登录 → 分享房间 → 复制URL与二维码解码一致 → 手机/另一浏览器打开 → 错误密码不泄漏内容 → 正确密码进入WebRTC → 查看两个Pi实例/会话 → 连接路径显示direct或TURN。不要未经允许向真实Pi发送测试prompt或调用付费模型；可用仓库内隔离合成测试。

如需正式公网端到端测试，先确认工具和用户授权，不通过改名、换通道或绕过方式重复被拒绝的操作。受限网络、VPN/UDP失败、缺TURN/TLS、缺手机真机测试等必须明确记录。使用公共网站的JavaScript仍需信任该站点，不宣传绝对零信任。

升级回退始终保留旧程序、服务文件和身份，不为了重新出现初始化页清空状态。工作结束提供实际安装路径、服务名称、如何打开分享入口、已验证项目及未验证项，不输出密钥、原始会话、无关命令历史或虚构的上线结果。
