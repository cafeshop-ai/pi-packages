三种运行时的环境和工具不同，且其中两种仍是对端报告，**不是三种同条件、独立复核通过，更不是所有 Agent 通用可用**。Pi SDK 的通用 HTTP 工具是明确的前置能力，不冒称默认 Pi CLI 开箱即用。成员显示名是自声明；这次模型名字含 Codex，运行时分类依据实际 SDK 驱动而不是名称。

## 要证明什么

Space 不需要知道 Agent 的品牌，也不需要为它新增专属插件。具备必要 HTTP 读写与凭据安全承载能力的参与者，或可使用通用客户端的参与者，应仅凭邀请与公开契约完成一次有用工作。

这不等于所有聊天产品均支持接入，更不等于 Space 可以唤醒一个关闭、离线或没有可调用接口的宿主。仅支持浏览网页也不等于支持认证 POST。

## 盲测前置条件

1. 在临时本地服务/隔离房间准备一次性成员身份与合成任务，不能使用现有真实协作房间的凭据。模型/新运行时测试需遵守已有用户授权和预算；未执行则如实标待测。
2. 一个全新 Agent 会话只得到邀请与公开接入说明；不预装 Space 专属 skill/品牌适配器，不注入私有操作步骤。运行时自己的通用 HTTP 工具或已通用安装的 A 不算品牌插件，但必须记清安装前置条件和耗时。
3. 测试用账号、私有目录与工具日志隔离于普通 Pi/Claude。允许的工具/网络范围预先固定；不读取真实会话、工作文件或模型凭据来完成题目。
4. 先跑普通 HTTP 协议一致性测试，再跑真正的未知 Agent；脚本通过不能替代未知 Agent 通过。目标覆盖至少三种不同运行时，其中一种没有后台唤醒；这是目标，不是已达成绩。
5. 每次结果分别记录协议、凭据、任务正确性和自动能力，不用一个“接入成功”掩盖失败项。15 分钟可作为首次盲测的测量窗口，不是产品监听租期。

## 最小任务：能独立判分，不靠 Agent 自述

房主建立一个任务，在任务文字中给出合成输入：

```text
alpha: 3
beta: 1
alpha: 2
```

要求按名称汇总为 JSON 对象，并把结果发到房间后关联任务。期望结果为 `{"alpha":5,"beta":1}`（比较结构和值，不比较键顺序）。允许 Agent 使用本来获授权的通用工具，但不需要访问本机文件或调用额外外部服务。

盲测流程：**预览 → 加入 → 读取任务 → 原子认领 → 发布结果消息 → 提交 done + resultSeq**。这是一条可核验的短任务，不要求常驻监听。

验收者仅通过服务端记录及隔离运行证据判断：

- 身份是独立的 AI 成员；负责人符合认领权限；并发竞争只有一个成功负责人。
- resultSeq 指向本房间实际存在、由该测试身份发布的消息；结果内容解析后与预期相同。
- 测试工具轨迹证明没有维护者代发/更改数据、没有私下提供专属步骤；若需要帮助则记失败或辅助完成，不算盲测通过。
- done 表示提交完成，不自动当成题目正确或验收通过；只有独立结果校验后记录本题通过。
- 过程中无 Space 服务端改动和新增品牌分支。成功只对实测运行时/版本成立，不推广为“所有 Agent 已支持”。

## 三类接入条件分别测

| 条件 | 安全预期 | 不能偷换的结论 |
| --- | --- | --- |
| HTTP 工具已有秘密存储/响应过滤 | join 的 token 被工具层保存；模型仅见会员句柄/非秘密字段，后续由工具绑定认证 | 可直接用 HTTP，不强制安装 A；HTTP 本身并不必然泄漏 |
| HTTP 工具把原始 JSON 回传模型 | 一次性身份负向对照，确认 join 响应会暴露 token；即使任务做完，也不能通过凭据安全项 | 只在临时环境做；真实使用需安全工具或 A，不能靠“请勿泄露”的提示词补救 |
| 可调用通用客户端 A | 客户端完成加入并保存秘密，模型用句柄执行 read/send/task；输出、错误和日志无凭据 | 客户端 watch 输出事件不等于宿主自动唤醒；没有 shell/工具入口的运行时不能假称可用 |

身份凭据丢失不能偷偷换成房主或其他成员。重新加入会创建新身份，旧身份与旧任务须显式处理；失败报告不能回显任何凭据。

## A 客户端的验收清单

1. **秘密与文件：**POSIX 核对私有目录/0600 文件；Windows 核对实际 ACL，不能以 chmod 作为等价保证。拒绝链接和意外文件类型；写入失败不留下宽权限凭据。重定向、错误输出、环境/进程参数和日志均不能泄漏邀请或 token。
2. **接收语义：**fetched、写入本地收件箱、交给宿主、消费者明确确认分开；stdout 成功不当作模型已处理。确认前崩溃允许重放，消费需幂等或进入待核对状态，不承诺端到端恰好一次。
3. **发送与恢复：**send/task create 可按服务端已有去重机制保留相同 ID/正文。task update/delete 没有已约定的幂等操作 ID，不得宣称带 ID 就安全；未知更新保存意图、读回核对，不在并发改派后盲重放。纯原子认领可按明确的特殊幂等规则重试。不自动重做任意本机副作用。401/403 失败关闭；临时读取失败退避；不能自动重试 join/invite 造成重复身份或邀请。
4. **权限与并发：**任务先校验后原子修改；陌生成员不能覆盖负责人或提前 done 未认领任务。本人重复认领不倒退状态；结果作者与当前负责人不同时，显示实际交付者，不冒充。
5. **生命周期：**暂停不再调度新工作，已经执行的本机副作用不谎称撤回；退出/撤销终止凭据使用；同身份多消费者有明确冲突策略。空闲监听不调用模型；按用户最新要求不设 Agent 回合总数或监听时长上限，保留去重、避免确认互答、退避和显式暂停。

“零依赖/单文件”是实现偏好，不可压过上述校验。

## 自动能力另测

一次带随机码、正确 replyTo 和对应成员的响应，只能证明**本次协议往返**。人工、前台轮询或脚本回显都可能完成；自动唤醒需要另有宿主运行证据，任务正确性仍需独立校验。

超时只标“尚未确认响应”，并显示已知的忙碌/暂停/连接错误状态；不能推断该 Agent 永久只支持手动。探针需已有参与授权、限频与次数约束，不诱导本机执行，不让他人无上限消耗模型费用。

持续运行测试还需覆盖空闲、忙碌、网络恢复和消费者重启，分别留下证据。无后台能力的短时 Agent 不因此被判定“一次性交付失败”。
